# Implementation Plan: Aplicando la Fábrica de Agentes a Datanestiq (Dogfooding)

¡Excelente aclaración! Tienes toda la razón: la mejor forma de vender esta Metodología (Spec 004) es que **Datanestiq sea su propio primer Caso de Éxito**. Debemos someter tu actual prototipo (`index.html`) a la "Línea de Ensamblaje" de los agentes que acabamos de crear para que el texto de tu web sea brutalmente persuasivo y consultivo.

## 1. Summary
**Objetivo Principal:** Orquestar a los agentes creados en la Spec 004 para que reescriban y estructuren todo el *copy* del `index.html` de Datanestiq, elevando la comunicación estática actual a un estándar High-Ticket B2B utilizando los frameworks StoryBrand, PAS y AIDA.

## 2. Technical Context
- El archivo objetivo es `c:/xampp/htdocs/datanestiq/prototype/index.html`.
- La estructura visual (CSS/Tailwind) y funcional (Microexperiencias Spec 002) se mantendrán intactas; **solo alteraremos los textos (Copywriting)**.

## 3. Proposed Changes (El Pipeline en Acción)

### 3.1. Hero Section (Actuando como Agente 02)
- **[MODIFY]** `index.html` (Above the Fold): Aplicaremos el framework StoryBrand para reescribir el Titular (H1) y Subtitular (H2). Dejaremos de hablar de "Nosotros" y pasaremos a hablar de "El dolor del CFO/CTO" y cómo Datanestiq es la solución inmediata.

### 3.2. Body & Servicios (Actuando como Agente 05)
- **[MODIFY]** `index.html` (Sección de Soluciones): Reescribiremos los bloques de servicios (Chatbots, Automatización, Data) usando el enfoque de Venta Consultiva. Cambiaremos descripciones genéricas por resultados cuantificables y orientados a la reducción de fricción operativa.

### 3.3. Metodología y Autoridad (Actuando como Agentes 04 y 06)
- **[MODIFY]** `index.html` (Sección Metodología): Reescribiremos la narrativa de cómo trabajamos (el ciclo GitHub SDD y Spec-Kit) para que suene menos a un manual técnico y más a una "Ventaja Competitiva Injusta" para el cliente (Framework STAR).

### 3.4. Trust Layer & Friction Killing (Actuando como Agentes 09 y 10)
- **[MODIFY]** `index.html` (Sección CTA y Diagnóstico IA): Inyectaremos copy de reversión de riesgo. Ajustaremos el llamado a la acción del Flujo de Diagnóstico (Wizard) para que sea una oferta irrefutable.

## 4. Verification Plan
- Validar visualmente en el prototipo que los nuevos textos no rompan el diseño en grilla ni los contenedores de Glassmorphism.
- Asegurar que no quede rastro de lenguaje de IA ("En resumen", "Sinergia", "Adéntrate").
